## 1. 当前定位

《雾下余粮》当前是一个以静默圣遗物为安全锚点、以远征探索为主要行为的 2D 格子回合制生存探索 Demo。

V2 保留“搜打撤”的风险决策：

- 出发前准备；
- 风险与收益判断；
- 继续深入还是主动返回；
- 携带能力与回程压力；
- 死亡损失。

V2 不再保留“副本 + 撤离点”的空间结构。当前方向是：

> 保留搜打撤的风险决策，不保留搜打撤的副本结构。

当前核心循环：

```text
静默圣遗物 / 基地区域
→ 离开安全区
→ 探索持久世界
→ 发现地形、资源、怪物、巢穴和事件
→ 采集、绕行、战斗或继续深入
→ 根据生命、抗性、饥饿、背包和危险决定是否返回
→ 主动回到静默圣遗物
→ 恢复抗性、净化异变肉
→ 再次向更远区域探索
```

目前“返回圣遗物即结束一次远征”、基地储存、建设及新的 Demo 目标尚未完整实现，以上循环后半段仍是 V2.2～V2.4 的设计方向。

## 2. Current V2 / Implemented

### 2.1 入口与持久世界

- 主菜单提供开始、继续、配置、关于和重置存档。
- 开始或继续会直接进入世界地图，不再经过庇护所 UI。
- 默认世界为 100×100，配置允许 20～200。
- 世界使用固定 Seed；相同世界配置与 Seed 会重建相同地形、圣遗物、出生点、树木和石矿。
- 静态世界由 Seed 重建，存档不重复保存 100×100 全量地形。
- 玩家世界位置、世界回合、木材、石材及变化后的资源状态会写入存档。
- 世界身份或 Seed 改变时重建世界层，角色层旧数据仍按现有迁移逻辑保留。
- 战斗留下的格子级动态污染属于世界层；世界身份或 Seed 改变时不会带入新世界。

### 2.2 地形与生成

- 使用海拔、湿度、污染三类确定性噪声。
- 已有八类地形：草地、土地、森林、水、浅水、石山区、泥地、腐化地。
- 水和石山区不可通行；浅水及其余地面当前可通行。
- 静默圣遗物生成在世界中心附近，周围会强制整理为可通行、低污染的起步区。
- 旧 V1 固定怪物与巢穴布局以圣遗物附近为中心平移进 100×100 世界。
- 目前没有 Macro Region；地形仍主要是格子级噪声结果。

### 2.3 静默圣遗物

- 静默圣遗物是地图实体，不是当前主流程中的独立庇护所界面。
- 精神保护范围 `radius = 8`，`madnessProtection = 100`；玩家位于该范围内且所在地形污染不高于 100 时，环境污染结算被屏蔽。
- 玩家位于 8 格饥饿保护范围内移动不消耗饥饿。
- 世界安全范围保持独立字段 `safetyRadius = 8`；当前数值与精神、饥饿保护一致，但概念没有重新合并。
- 旧 V2.1.1 默认配置组合会把 `relicRadius = 5` 迁移为 8；其他自定义保护半径保持原值。
- 怪物的 Wander、Alert、Chase 和 AttackIntent 均不会进入安全区；追击安全区内玩家时会转入现有 Return 或 Cooldown。
- 巢穴产怪会过滤安全区内候选位置；初始怪物及旧运行快照中的怪物也会被安置到安全区外。
- 地图以低透明度连续光域表现安全范围，不显示格子边界或大圆圈 UI。
- 玩家站在圣遗物格按 E 可打开管理界面。
- 管理界面可查看保护规则、净化值、木材和石材。
- 可消耗净化值恢复疯狂抗性，或选择一块异变肉进行完全或部分净化。
- 精神污染保护仍是阈值判断；空间安全区不清怪、不回血，也不让玩家绝对无敌。

### 2.4 世界资源与采集

- 树木和石矿是可交互的世界资源实体。
- 站在资源格按 E 进行采集，每次采集推进一个地图回合。
- 树木默认 2 点生命，耗尽后掉落 2 木材。
- 石矿默认 3 点生命，耗尽后掉落 2 石材。
- 资源剩余生命和耗尽回合会持久化。
- 木材和石材进入 `WorldSave.inventory`，当前尚无消费用途。
- 树木具有恢复字段，但尚未接入按世界回合恢复的运行时结算；石矿当前不恢复。

### 2.5 探索与战争迷雾

- 逻辑仍为四方向格子移动，地图采用离散回合。
- 100×100 世界通过最多 20×20 的跟随视口显示。
- 支持方向键、WASD、点击相邻格和移动端方向键。
- 三态战争迷雾：未探索、已探索记忆、当前可见。
- 当前可见区域正常显示；离开视野后进入低亮度记忆状态。
- 未探索区域使用实体黑色遮罩，不使用雾团切口、柔边或模糊边界。
- 玩家迷雾和敌人视野均支持障碍遮挡；当前默认玩家地形视线遮挡仍可配置。
- 记忆状态保留最后看到的敌人与尸体，不显示其实时状态变化。

### 2.6 敌人、巢穴与战斗

- 现有敌人状态机继续复用：
  `Idle / Wander / Alert / Chase / AttackIntent / Return / Cooldown / Dead`。
- 普通敌人有四方向朝向、扇形视野、障碍遮挡、警觉、追踪、攻击意图、返回和冷却。
- 相邻但位于主动敌人背面的玩家不会只因距离被发现；主动进入敌人格会接敌。
- 巢穴使用统一怪物实体，可按回合、存活子怪上限和总产出上限生成子怪。
- 巢穴不会主动接敌；玩家主动进入巢穴格时进入普通战斗。
- 接敌后冻结地图并进入独立回合制战斗。
- 战斗支持攻击、防御、道具和逃跑；速度影响先手。
- 胜利后在世界格留下尸体；尸体可切割并生成逐块记录污染值的异变肉。
- 怪物、尸体、巢穴和迷雾运行时状态会进入当前运行快照，刷新后可继续。

### 2.7 生命、饥饿、疯狂与污染

- 生命、疯狂、疯狂抗性和异变肉仍保存于角色层存档。
- 疯狂抗性默认 10/10，只能通过圣遗物恢复。
- 饥饿默认 100/100，只在实际移动时消耗；圣遗物保护范围内移动不消耗。
- 战斗、等待、切割、事件推进和使用道具不直接扣除饥饿。
- 饥饿归零后继续移动会受到伤害。
- 当前每次启动/恢复世界运行时，饥饿仍从玩家配置初始化；它尚不是持久角色状态。
- 地形带有生成时确定的局部污染值；环境污染按实时周期结算，先扣抗性，再把溢出加入疯狂。
- 圣遗物保护判定使用玩家当前格的地形污染值。
- 玩家与怪物在战斗中实际损失的 HP 按 1:1 进入 `sceneMadness`。
- 同一份实际 HP 损失也会写入损血者发生损血时所在世界格的 `dynamicCorruption`。
- 玩家与怪物位置在接敌时进入战斗上下文快照；胜利移动、逃跑、死亡或结束回调不会改变污染落点。
- `dynamicCorruption` 以 `"x,y": value` 稀疏结构写入 `WorldSave`，同格累计且不限制为 0～100。
- Seed 生成的基础污染保持不变；统一读取概念为 `baseCorruption + dynamicCorruption = effectiveCorruption`。
- 动态污染不扩散、不衰减、不自动清除，暂不参与环境疯狂伤害、圣遗物保护、生态、生成或地形判定。
- 地图以四档低饱和暗紫红叠加和腐化纹路反馈动态污染，未探索区仍由战争迷雾遮盖。
- 异变肉食用时增加该肉块当前剩余污染，不被疯狂抗性抵消；同时恢复生命和饥饿。
- 疯狂阶段会改变攻击倍率，并提供阶段文案、低语及界面表现。

### 2.8 随机事件、配置、音频和展示

- 已有 8 个数据驱动地图事件，支持权重、疯狂条件、选择和即时结果。
- 配置系统支持分类表单、本地保存、恢复默认、校验和 JSON 导入/导出。
- V1 地图编辑器仍可编辑旧关卡地图与试玩草稿，但不能编辑程序世界地形或覆盖层。
- 已有 22 个程序化 WAV 音效，支持解锁、缓存、变体、冷却、静音、音量和加载失败回退。
- 桌面和移动端均有响应式布局。
- 页面显示 `V2.1.2 · Silent Relic Protection Alignment` 版本号。

## 3. Legacy / Compatibility

以下代码或数据仍然存在，用于旧存档、旧配置、地图编辑器或复用成熟运行时。它们不应继续被描述为 V2 当前游戏规则。

### 3.1 V1 角色与结算字段

- `safeFood`
- `expeditions`
- `successfulExtractions`
- `expeditionFailures`
- `totalMonsterMeatReturned`
- `lastResult`
- `farm`
- Demo 目标及首次撤离引导状态

新存档仍会初始化这些字段，旧存档迁移也会保留它们。V2 正常世界没有撤离点，因此撤离次数和三次撤离目标在正常流程中无法推进。

### 3.2 `activeExpedition`

`activeExpedition` 的名称和部分字段来自 V1 单次外出，但它目前仍被 V2 运行时用于保存：

- 玩家即时状态；
- 当前回合和伪随机状态；
- 怪物、尸体和巢穴状态；
- 已访问格和迷雾记忆；
- 地图事件进度；
- 环境污染计时进度；
- `sceneMadness`。

格子级 `dynamicCorruption` 不在该快照内，而是直接属于 `WorldSave`。

因此它不是纯废弃字段。当前应将其理解为“世界运行快照的兼容容器”，未来在 V2.2 再考虑改名或拆分，不能在文档整理阶段直接删除。

### 3.3 庇护所 UI 与旧地图编辑器

- `renderShelter()` 及其中的储备粮、旧圣遗物、灰麦种植格、外出入口和 Demo 目标仍在代码中。
- V2 主菜单和正常完成回调不再进入该界面。
- V1 地图配置仍包含 20×20 尺寸、撤离点、障碍、随机刷怪区和固定怪物点。
- V2 只复用其中的迷雾、环境污染和固定怪物布局等成熟配置；程序世界运行时会将撤离点清空。
- 地图编辑器仍编辑这份 V1 关卡配置，当前不等价于程序世界编辑器。

### 3.4 旧外出结算函数

- `extract()`、`succeedExpedition()`、`failExpedition()`、外出总结和旧目标判断仍在运行时或 UI 代码中。
- V2 正常世界不生成撤离点，因此成功撤离不是可达的常规流程。
- 玩家战斗死亡仍会经过旧失败结算路径，然后在圣遗物旁重新进入世界；其中死亡资源损失规则尚未按 V2 重新设计。

## 4. Deprecated / Superseded

以下玩法已被 V2 主流程取代：

- 主菜单 → 庇护所 UI → 户外副本；
- 唯一 20×20 单次户外地图作为主世界；
- 每次外出重新生成一张独立世界；
- 撤离点和撤离读条作为正常探索出口；
- 成功撤离后返回庇护所；
- “3 次成功撤离 + 12 块异变肉”的 Demo 胜利目标；
- 外出失败次数上限和食物库存耗尽作为 Demo 失败条件；
- 用外出次数推进庇护所灰麦；
- “当前阶段不做程序化大地图”的旧限制。

这些内容可以继续存在于历史设计文档和兼容代码中，但不能作为 Current V2 功能宣传或验收标准。

## 5. Reserved

- `enableOutdoorFarming` 与作物 `allowOutdoor`：户外种植预留，默认关闭。
- 树木资源状态中的恢复回合字段：资源恢复预留，尚无结算。
- 怪物 `carriedLoot`：携带物掉落表预留，当前为空。
- 多件装备配置：装备选择预留，当前只读取默认装备。
- `AudioService.playBgm/stopBgm`：BGM 接口预留，当前没有 BGM 内容。
- 地图事件的条件、权重和永久记录字段：可继续扩展事件。
- 污染生态接口：动态污染总账已经建立，但对生成、生态和规则的反向影响仍只保留为后续演进位置。
- 地图编辑器的图层、多选、框选和批量操作：旧编辑器体验预留，不代表程序世界可编辑。

Reserved 只表示已有字段、接口或演进位置，不代表对应玩法可用。

## 6. Not Implemented

- Macro Region 和有辨识度的区域生成。
- 按区域生成怪物、巢穴、资源与事件的生态层。

### 6.2 更远期内容

- 养殖与动物实体。
- 自由建筑、墙、门、房间、家具、屋顶和防守模拟。
- 多个圣遗物、升级、过载和多基地。

- 大型异常地点、Boss、NPC、任务和剧情。
- 制作树、装备掉落、换装、耐久、随机词条、交易和经济。
- 无限世界、Chunk 流式加载和后台完整生态模拟。
- 服务端账号、云存档、排行榜和联机。

## 7. 已知技术与体验债务

- `activeExpedition` 同时承载 V1 外出语义和 V2 世界运行快照，职责与命名不清。
- V2 角色位置、资源状态和动态污染写入 `WorldSave`，但怪物、尸体、迷雾及 `sceneMadness` 仍放在 `activeExpedition`。
- 玩家饥饿在 `GridExplorationRuntime.start()` 中由配置重新初始化。
- 旧 V1 配置、界面、结算和引导文案仍存在，部分配置页仍显示撤离与庇护所概念。
- V2 怪物和巢穴不是生态生成，只是把旧固定布局平移到圣遗物附近。
- 木材和石材已能获得，但没有用途。
- 动态污染已经持久化并可视化，但尚不反向影响环境伤害、圣遗物保护或生态。
- 死亡后仍借用 V1 外出失败结算；玩家生命重置并回到世界，资源损失边界尚未正式定义。
- README 和当前状态文档完成本轮修正后，旧 V1 设计文档仍保留历史原貌。

## 8. 当前验证边界

自动测试已覆盖：

- 同 Seed 世界复现；
- 起步安全区；
- 八类地形和两类基础资源；
- 世界存档迁移与资源状态恢复；
- V2.0 旧存档缺少动态污染字段时的兼容迁移；
- 双方不同格落点、overkill、多回合累计、逃跑、死亡、战斗坐标快照及结束回调防重复；
- 战斗实际 HP 损失与新增动态污染的守恒；
- 动态污染保存恢复、世界身份隔离及基础污染不变；
- 圣遗物饥饿保护和污染屏蔽；
- 资源采集与木石库存；
- V1 配置、存档、战斗、敌人 AI、迷雾、方向视野、巢穴、疯狂、音频和事件回归。

尚未充分覆盖：

- 程序世界的长时间人工节奏；
- 移动端实机完整远征；
- 配置编辑器 DOM 交互；
- 战斗或事件弹窗中刷新后的精确中间态；
- V2 死亡和返回圣遗物的完整体验；
- 大量资源状态下的存档体积与性能。
